# 书评内容填写指南

> 适用后台：书籍管理 / 发布设置 / SEO。写新书评前先看这一页，避免漏字段或发布后才发现问题。

## 一、发布设置各字段的作用

| 字段 | 主要作用 | 填写建议 |
| --- | --- | --- |
| 发布状态 | 控制书籍是否出现在公开站点 | 未完成时用「草稿」；内容、封面、SEO 都确认后再切「已发布」 |
| Slug | 书籍在公开站点的 URL 标识，例如 `/books/yi-ru-ji-wang` | 新建时留空自动按书名生成；已发布后尽量不要再改 |
| 分类 | 一本书的主分类，用于后续分类页、筛选、导航 | 只填一个稳定的大类，例如：小说、历史、商业、心理、传记 |
| 标签 | 多个细关键词，用于标签页、相关推荐、站内搜索 | 一本书建议 3–6 个，用逗号分隔；不要堆无关词 |
| 系列 | 把同一系列的书归到一起 | 只有确实成系列时才填，例如「文明的故事」 |
| 系列序号 | 控制同一系列内的展示顺序 | 有系列时填 `1`、`2`、`3`；没有系列就留空 |
| 发布时间 | 控制公开站点何时展示 | 立即发布就保持当前时间；未来时间会等到时间到了才公开 |
| SEO 标题 | 搜索结果标题、浏览器标签标题、分享卡片标题 | 不填默认用书名；建议 30 个中文字左右 |
| SEO 描述 | 搜索结果摘要、分享卡片描述 | 不填回退到书籍简介；建议 70–120 个中文字 |

### 分类和标签的区别

- **分类**：大类，通常一本书只有一个。
- **标签**：关键词，可以多个，用来描述主题、人物、场景、流派等。

示例：

```text
分类：商业
标签：商业, 投资, 人性, 历史
```

## 二、当前实际生效情况

- 公开 API 只返回 `status = published` 且 `published_at <= 当前时间` 的书籍和评论。
- 草稿不会出现在公开站点、公开 API、sitemap。
- Slug 已生成并保证唯一；后续会用于公开站点的可读 URL。
- 分类、标签、系列、系列序号目前主要是内容组织字段，公开的分类页/标签页/系列页还没有做，但数据已经存好，后面可以直接用。
- SEO 标题和 SEO 描述已经用于公开详情页的 `<title>`、`meta description`、OG/Twitter 分享信息。

## 三、推荐填写流程

1. 新建书籍：书名、作者、封面、简介。
2. 填分类、标签；如果属于系列，再填系列名和系列序号。
3. Slug 留空，让系统按书名自动生成；检查生成的 slug 是否可读。
4. 填 SEO 标题和 SEO 描述（可选，但建议每本都写）。
5. 发布状态先保持「草稿」，保存。
6. 写评论；评论也先保持草稿，确认后再发布。
7. 预览公开页面，确认标题、封面、简介、评论都正常。
8. 把书籍和评论切换为「已发布」。

## 四、示例

以《一如既往》为例：

```text
书名：一如既往
作者：Morgan Housel
Slug：yi-ru-ji-wang
分类：商业
标签：商业, 投资, 人性, 历史
系列：留空
系列序号：留空
发布状态：已发布
SEO 标题：《一如既往》书评：在变化中寻找不变 | 书评集
SEO 描述：《一如既往》讲的是世界一直在变，但人性、风险和周期中有些东西始终不变。本文整理书中的核心观点与阅读笔记。
```

## 五、常见错误

- **发布后修改 Slug**：旧链接可能失效。已发布书籍尽量不改；确实要改时，需要同时考虑旧 URL 重定向。
- **分类和标签混用**：分类填成「投资, 历史」，标签又填「商业」，后面筛选会乱。
- **标签堆砌**：堆很多不相关关键词不会提升 SEO，反而让内容显得不专业。
- **SEO 标题太长**：搜索结果会被截断，核心信息放前面。
- **SEO 描述直接复制简介**：可以，但最好单独写一版更适合搜索展示的摘要。
- **系列序号没有系列名**：单独填序号没有意义。
- **状态已发布但内容是半成品**：先草稿，确认后再发布。

## 六、发布前快速检查

- [ ] 书名、作者、封面、简介完整
- [ ] 分类只填了一个主分类
- [ ] 标签 3–6 个，和内容相关
- [ ] Slug 可读且没有重复
- [ ] 有系列时才填系列名和序号
- [ ] SEO 标题、SEO 描述已填写（或确认使用默认值）
- [ ] 书籍和评论都确认过公开页面
- [ ] 发布状态为「已发布」
- [ ] `published_at` 不是未来时间（除非就是要定时发布）
